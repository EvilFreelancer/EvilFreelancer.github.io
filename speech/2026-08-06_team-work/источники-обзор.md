## 0. Затравка, посты и проект coddy-agent

### Пост evilfreelancer/1734, согласование Cursor и Claude Code
https://t.me/evilfreelancer/1734

- **Тип:** заметка из практики (канал автора).
- **Суть:** когда в одном проекте работают несколько агентов, у каждого своя папка правил, Cursor берёт `.cursor/rules/*.mdc`, Claude Code `.claude/rules/*.md`. Структура похожа, формат разный, друг о друге они не знают. Решение, держать оба набора в репозитории, писать правило один раз и синхронизировать вторую папку, оба коммитить вместе.
- **Что взяли:** затравка всей лекции и ядро части 2 (Rules Sync).

### Пост evilfreelancer/1732, почерк модели
https://t.me/evilfreelancer/1732

- **Тип:** наблюдение из практики (канал автора).
- **Суть:** проект, начатый в Claude Code на Opus, Codex на GPT тянет плохо, и наоборот. Флагманская модель оставляет в коде свой почерк, структуру и идиомы, чужой почерк другая модель читает хуже и норовит переписать. Код от слабых моделей и от Model Auto мигрирует между агентами легче, почерк усредняется.
- **Что взяли:** часть 1, аргумент за единообразие, либо один агент, либо жёсткие общие правила.

### Пост evilfreelancer/1846, Codex и правила
https://t.me/evilfreelancer/1846

- **Тип:** заметка из практики (канал автора).
- **Суть:** в Codex нет папки правил с glob-условиями, контракт живёт в AGENTS.md (включая вложенные по каталогам). Побочный эффект из практики автора, Codex ломал старые фичи и правил упавшие тесты вместо кода.
- **Что взяли:** часть 2 (различие механик правил, у Cursor и Claude Code условия по путям, у Codex иерархия вложенных AGENTS.md) и часть 3 (правило "дифф тестов ревьюится отдельно"). Кейс подаётся как опыт конкретной команды, не как общий вывод об архитектуре Codex.

### coddy-agent, AGENTS.md
https://github.com/coddy-project/coddy-agent/blob/main/AGENTS.md

- **Тип:** корневой контракт проекта для агентов.
- **Суть:** проект на четырёх слоях (CLI, ядро оркестрации, сессии, внешние каналы). Принципы, сборка по тегам, документация как контракт (DESIGN.md, OpenAPI, правила в `.cursor/rules/*.mdc`), тесты перед кодом. Маршрут разработчика, прочитать правила, тесты, реализация, обновить доки, полная регрессия.
- **Что взяли:** живой кейс для частей 2 и 3, связка "правила + спека + TDD" как контракт команды.

### coddy-agent, DESIGN.md
https://github.com/coddy-project/coddy-agent/blob/main/DESIGN.md

### coddy-agent, .cursor/rules/workflow.mdc
https://github.com/coddy-project/coddy-agent/blob/main/.cursor/rules/workflow.mdc

- **Тип:** правило-воркфлоу для агента.
- **Суть:** BDD/TDD-процесс. Фича, красный (падающий тест), зелёный (минимум кода), `make test`, обновить OpenAPI и доки, если затронут HTTP, `make lint`. Багфикс, регресс-тест, починка, тесты и линтер. Финальный чек-лист включает проброс правил `.cursor/rules/` в `.claude/rules/`.
- **Что взяли:** конкретный порядок приёмки для части 3 и шаг Rules Sync для части 2.

## 1. Спека и правила как контракт

### AGENTS.md, спецификация формата
https://agents.md/

- **Тип:** сайт открытого межинструментного стандарта.
- **Суть:** AGENTS.md - обычный Markdown без обязательных секций, читается Codex, Cursor, Copilot, Gemini CLI и другими. Поддерживаются вложенные файлы, для конкретного файла действует ближайший AGENTS.md по дереву каталогов, более глубокий приоритетнее.
- **Что взяли:** часть 2, статус стандарта, вложенные файлы и приоритет ближайшего. Проверено 2026-08-03.

### Cursor Rules и Claude Code memory, официальные доки
https://docs.cursor.com/context/rules и https://code.claude.com/docs/en/memory

- **Тип:** официальная документация, источник истины по форматам.
- **Суть:** у Cursor правила в `.cursor/rules/*.mdc` с фронтматтером (description, globs, alwaysApply), четыре режима подключения, вложенные каталоги. Cursor также читает корневые AGENTS.md и CLAUDE.md. У Claude Code иерархия CLAUDE.md, папка `.claude/rules/*.md` с привязкой к путям, импорты через @, симлинк как вариант для Unix.
- **Что взяли:** часть 2, точные пути, форматы и способ связать CLAUDE.md с AGENTS.md импортом.

### GitHub Spec Kit, spec-driven development
https://github.com/github/spec-kit и https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/

- **Тип:** open-source тулкит и анонс.
- **Суть:** спека в центре разработки с агентом. Актуальный цикл, constitution (принципы проекта), specify (что строим), plan (как строим), tasks (разбивка с зависимостями и путями файлов), implement (реализация по списку), команды `/speckit.*`. Markdown-файлы - источник истины, интеграции с Claude Code, Cursor, Copilot, Codex и другими.
- **Что взяли:** часть 2, спека как общий язык для разных агентов. Цикл обновлён с трёх шагов до пяти по состоянию тулкита на 2026-08-03.

## 2. Приёмка, BDD и TDD с агентами

### Пост evilfreelancer/1753, правило BDD
https://t.me/evilfreelancer/1753

- **Тип:** правило из практики команды автора.
- **Суть:** запрос на функционал или багфикс от бизнеса заводится feature-тестом огуречного формата, edge-кейсы к фиче добираются юнит-тестами.
- **Что взяли:** часть 3, живое правило приёмки, разводящее BDD (язык с бизнесом) и юнит-уровень.

### Гайды по TDD с агентом
https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/guide/workflows/tdd-with-claude.md, https://www.nathanfox.net/p/taming-genai-agents-like-claude-code, https://alexop.dev/posts/custom-tdd-workflow-claude-code-vue/

- **Тип:** гайды и разборы.
- **Суть:** агента просят писать тесты первыми и явно проговаривают, что это TDD, иначе он реализует сразу и подставляет тест под готовый код. Цикл красный-зелёный-рефактор даёт агенту проверяемую цель. Хук PostToolUse запускает линтер и быстрые проверки после каждой правки.
- **Что взяли:** часть 3, явное проговаривание TDD, хуки для быстрых проверок. Полный прогон тестов оставлен контрольным точкам и CI, гонять его на каждую правку дорого.

## 3. Изоляция и параллельность, git worktrees

### git worktree, официальная документация
https://git-scm.com/docs/git-worktree

- **Тип:** первичная документация git.
- **Суть:** `git worktree add` создаёт дополнительное рабочее дерево репозитория в отдельной папке, история и объекты общие. Одна ветка может быть выписана только в один worktree.
- **Что взяли:** часть 4, механика и ограничение про одну ветку.

### Практические гайды по worktree для агентов
https://www.augmentcode.com/guides/git-worktrees-parallel-ai-agent-execution, https://medium.com/google-cloud/run-multiple-coding-agents-safely-with-git-worktrees-c2d237dbd6b2, https://www.mindstudio.ai/blog/git-worktrees-parallel-ai-coding-agents

- **Тип:** практические гайды.
- **Суть:** worktree даёт каждому агенту свою рабочую папку при общем репозитории, конфликтов за файлы в реальном времени нет, сведение через ветки и PR. Инструменты поверх worktree, Conductor, Vibe Kanban, Claude Squad (Vibe Kanban после закрытия компании-автора живёт как открытый проект). Фоновые агенты Cursor работают иначе, в изолированных облачных машинах. Подводный камень, worktree не разделяет node_modules и виртуальные окружения, зависимости ставятся в каждом дереве заново.
- **Что взяли:** часть 4, сценарий "несколько агентов на одной машине", инструменты и грабли с зависимостями. Semantic-конфликты worktree не отменяет, это добавлено в лекцию отдельно.

## 4. Узкое место, ревью, а не генерация

### When AI Teammates Meet Code Review
https://arxiv.org/abs/2602.19441

- **Тип:** научная статья.
- **Суть:** агенты подают PR быстрее, чем команда успевает ревьюить, разрыв между скоростью генерации и ёмкостью ревью растёт. Формула "verification is the bottleneck, not generation". Роль человека смещается к оркестрации, цели, доступы, приёмка результата.
- **Что взяли:** часть 5, главный тезис и цитата на слайд.

### Cloudflare, Orchestrating AI Code Review at scale
https://blog.cloudflare.com/ai-code-review/

- **Тип:** инженерный блог, продовые цифры, публикация апреля 2026 года.
- **Суть:** CI-нативная система ИИ-ревью, до семи специализированных агентов на мерж-реквест плюс координатор. За первые 30 дней 131 246 прогонов ревью на 48 095 MR в 5 169 репозиториях, медианное ревью 3 минуты 39 секунд, средняя цена прогона 1,19 доллара. Принудительное одобрение в обход ИИ-ревью (break glass) применено 288 раз, это 0,6% MR.
- **Что взяли:** часть 5, точные цифры на слайд с атрибуцией. Проверено 2026-08-03.

### SlopCodeBench
https://arxiv.org/abs/2603.24755

- **Тип:** бенчмарк, научная статья (март 2026), сайт лидерборда и репозиторий SprocketLab/slop-code-bench.
- **Суть:** агент итеративно достраивает собственное решение под уточняющуюся спецификацию, 20 задач, 93 контрольные точки. Ни одна из 11 моделей не довела ни одну задачу до конца. Метрики качества траектории, verbosity (доля избыточного кода) и структурная эрозия (концентрация сложности). Код формально проходит чекпоинты и при этом деградирует.
- **Что взяли:** часть 5 (зелёная галочка не равна качеству) и часть 8 (аргумент за контрольные точки, без присмотра код разбухает). Узнал через пост https://t.me/evilfreelancer/1840. Проверено 2026-08-03.

## 5. Расширения, MCP, скилы, CLI

### Пост "Сила трёх"
https://t.me/evilfreelancer/1775

- **Тип:** пост автора.
- **Суть:** MCP, Skills и CLI не конкурируют, это разные слои воркфлоу. MCP даёт доступ к внешним системам, CLI закрывает рутинные и редкие операции в рантайме, Skills фиксирует правила работы и накапливает опыт.
- **Что взяли:** часть 6, рамка "разные слои, а не конкуренты".

### Как делать скилы правильно и собрать из них маркетплейс
https://habr.com/ru/articles/1062626/ и https://github.com/EvilFreelancer/rpa-skills

- **Тип:** статья автора на Хабре и репозиторий маркетплейса.
- **Суть:** повторяемые инструкции упакованы в скилы формата SKILL.md, разложены по репозиториям и собраны в маркетплейс rpa-skills, который подключается к Codex, Claude Code и Cursor одной командой. Лучшие практики сборки скилов и их валидация сабагентами.
- **Что взяли:** часть 6, переносимость формата SKILL.md между агентами как часть командного контракта.

### Model Context Protocol
https://modelcontextprotocol.io/

- **Тип:** официальная документация протокола.
- **Суть:** MCP-сервер - процесс, локальный или удалённый, отдающий агенту тулы к внешней системе. У удалённых серверов авторизация на стороне сервера, локальные получают секреты через конфигурацию клиента, рекомендованы минимальные права и осторожность с содержимым, которое возвращают инструменты.
- **Что взяли:** часть 6, аккуратная формулировка про секреты и правило "данные из MCP - данные, а не команды".

## 6. Паттерны многоагентности

### Anthropic, How we built our multi-agent research system
https://www.anthropic.com/engineering/multi-agent-research-system

- **Тип:** инженерный разбор от Anthropic.
- **Суть:** архитектура оркестратор-воркер. Ведущий агент планирует и запускает три-пять сабагентов параллельно, у каждого свой контекст, цель, формат и границы. Многоагентная связка обошла одиночный Opus 4 на 90,2% на их внутренних задачах поиска. Цена, агент примерно вчетверо дороже чата по токенам, многоагентная система примерно в пятнадцать раз. Ориентир масштаба, простой запрос - один агент, сравнение - два-четыре, широкое исследование - больше. Для задач с общим контекстом и плотными зависимостями схема подходит плохо.
- **Что взяли:** часть 7 целиком, схема, цифры расхода и ориентиры масштаба с атрибуцией "по данным Anthropic".

### Addy Osmani, The Code Agent Orchestra
https://addyosmani.com/blog/code-agent-orchestra/

- **Тип:** обзорная статья.
- **Суть:** паттерны многоагентного кодинга, сабагенты, команды агентов с общим списком задач, иерархии. Роль человека, план и спека, одобрение, верификация, интеграция. Принципы, специализация сильнее универсальности, сильная спека - рычаг, суждение не делегируется, AGENTS.md как накопитель общих знаний.
- **Что взяли:** части 7 и 8, паттерны и роль человека-тимлида.

### Claude Code, субагенты и агентные команды
https://code.claude.com/docs/en/sub-agents и https://code.claude.com/docs/en/agent-teams

- **Тип:** официальная документация.
- **Суть:** сабагент работает в отдельном контексте и не видит историю основной беседы, породить собственного сабагента не может, вложенности нет. Агентные команды (экспериментальная функция, выключена по умолчанию, включается переменной окружения), ведущий раскладывает работу в общий список задач, участники разбирают задачи, обмениваются сообщениями напрямую, зависимости задач разрешаются автоматически.
- **Что взяли:** часть 7, три схемы (оркестратор-воркеры, цепочка через ведущего, агентная команда) и ограничение про отсутствие вложенности. Проверено 2026-08-03.
